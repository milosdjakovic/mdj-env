## What the person asked for

A file per theme where colours are defined for dark and light, the current look as the
default, the repository's Aura palette as a second theme, and a theme switcher in Olm that
applies a theme live.

## The theme files

`dotfiles/hammerspoon/.hammerspoon/config/themes/<name>.toml`, one file per theme, the file
name is the theme name. Two sections, `[dark]` and `[light]`, each holding these keys with
`"#rrggbb"` or `"#rrggbbaa"` values.

```
text        primary text
subtext     secondary text
background  surface fill
border      surface border
accent      preview body text, the kit's accent token
meta        preview metadata, the kit's overlay token
path        preview path
note        preview note
highlight   optional, list cursor bar, derived as today when absent
selection   optional, field selection, derived as today when absent
```

A missing `[light]` falls back to `[dark]`. A missing required key falls back to the default
theme's value and logs once naming the theme and the key.

`default.toml` is hand written and holds exactly today's colours, taken from settings.surface
and settings.chooserTheme, with hs white values converted to hex. It carries a
`theme-exempt, <reason>` comment line since it is a hand chosen palette. Those colour values
then leave config/settings.lua, so the theme file is their one source. settings.surface keeps
cornerRadius and borderWidth, and the chooserTheme block goes, with its comment moved to
default.toml. bgDark is derived from the half and needs no key.

`aura.toml` is generated. Add `dotfiles/hammerspoon/theme-map` and
`dotfiles/hammerspoon/theme-emit` following the contract, the emitter writing
`.hammerspoon/config/themes/aura.toml` with the `Generated by theme-emit` banner. The map is

```
text       = foreground
subtext    = subtext
background = background
border     = dim
accent     = foreground
meta       = overlay
path       = comment
note       = tertiary
highlight  = highlight
selection  = selection
```

Since the package is now painted, delete `dotfiles/hammerspoon/theme-exempt`, list
`theme-map` and `theme-emit` in the package's `.stow-local-ignore`, and give each remaining
file holding hex a per file `theme-exempt, <reason>` line. Use the reasons the deleted file
gave, the processes icon brand colours will never be the palette's, the plugin preview
fallbacks wait for stage four. Run `./src/check-theme.sh` from the worktree root until it is
clean, and commit nothing.

## The reader and the store

`lib/ui/toml.lua`, pure Lua with no hs, reads the subset these files use, comments, blank
lines, `[section]` headers and `key = "string"` lines, and refuses any other line with an
error naming the file and line number.

`lib/ui/themes.lua` loads every `*.toml` in a directory the root hands it, answers the sorted
names, the current name and the colours for the current theme, and `set(name)`, which
persists the choice under the hs.settings key `olmTheme`, reconfigures the style and calls
an injected `onChange`. An unknown persisted name falls back to default with one warning.
The hs.settings call is injected so the unit loads in plain Lua for tests.

root/uispec.lua builds the colour half of the spec from the current theme rather than from
settings. Every surface already resolves tokens per draw, so a switch shows on the next draw.
policy.chooserTheme still has readers outside the kit, the native provider and the plugin
panes, so compose derives a chooserTheme shaped table from the current theme and, on every
switch, rewrites that same table's contents in place, so readers that hold a reference follow
without a reload. Note in a comment that stage four retires this view.

The theme directory reaches compose through policy, the way storage paths already do, from
init.lua and config/settings.lua `paths`.

## The switcher

A second row on the OLM settings top level, Theme, its subtitle naming the live theme.
Choosing it pushes a child page, Back first, then one row per theme, the current one marked
with the same green circle the placement page uses. Choosing a theme applies it at once and
answers stay, so the page keeps the highlight and the marker moves, exactly as the placement
page behaves. The words are root published, `themeName`, `themeNames` and `setTheme`, declared
in the settings manifest under `needs.data` with `source = "root"` and a `breaks` sentence,
the same shape as `overlayPlacementMode`. Update the plugin's README.

## Tests

Unit cases for the reader, valid file, a refused line naming the line number, and for the
store, names sorted, set persists through the injected settings, unknown persisted name falls
back, a missing light half and a missing key fall back. The parity probes in test/parity.sh
must still report identical against HEAD with the default theme, allowing a colour component
difference of at most one 8 bit step from the white to hex conversion, and report that
tolerance in the output.
